# External-token runner integration

The Linux `internal/runner` package implements the one-turn lifecycle in
[profile §6](../spec/v0-codex-refresher.md#6-external-token-delivery-and-one-shot-runner).
The command dispatches `run-codex`; production policy loading and the broker wire
adapter are separate integration work. The shipped command therefore refuses
ordinary execution with `lease_harness_unqualified` (69). There is no fixture,
environment or command-line switch that qualifies a production release.

The protocol subset follows the experimental JSON schema generated by Codex
0.163.0. General [app-server documentation](https://learn.chatgpt.com/docs/app-server)
is supporting context; other releases are refused even if their version text or
JSON shapes look compatible. Fixture success does not qualify vendor behavior.

## Embedding contract

Call `runner.Command` with a context cancelled on handled signals, command
arguments, stdin/stdout/stderr and `runner.Dependencies`. Dispatch
`runner.SupervisorMain(os.Args[1:])` before normal CLI parsing in the embedding
executable. A supervisor path may also identify that same reviewed executable.
It must implement this dispatch, rather than a shell or an arbitrary helper.

`Authority.Resolve` must read protected configuration and verify a complete
qualification record against the current schema, platform, runner version,
containment and configuration identities on every call. Its `Policy` binds the
peer/broker UID, account/vendor ID, profile, inference endpoint, policy generation,
executable path/digest, binding digest and qualified model/effort catalog.
`ConfigurationDigest` computes the supported configuration fingerprint for the
protected qualification flow; it is never an admission override.

`Connect` must open a fresh connection implementing:

```go
VerifyServer(context.Context, uint32) error
Hello(context.Context, HelloRequest) (HelloResult, error)
Request(context.Context, LeaseRequest) (Lease, error)
Renew(context.Context, RenewRequest) (Lease, error)
Release(context.Context, string) error
Close() error
```

The adapter must verify the kernel server UID before writing any protocol bytes,
use close-on-exec descriptors, honor every cancellation/deadline, cancel pending
requests on close, and implement idempotent release. `Lease.Token` ownership
transfers to the runner; the adapter must retain no material or expose it in
errors. Return `*runner.Refusal` for typed broker codes. Unknown errors become
fixed metadata. These types describe the adapter seam and do not encode broker
frames or canonical JSON.

The runner rechecks policy/configuration immediately before starting app-server.
It verifies the executable digest and runs the verified open file through a
private descriptor, preventing substitution between hashing and exec. Tokens
are delivered only through RPC stdin. The child receives a new environment with
explicit launch HOME/CODEX_HOME, fixed PATH and locale; neither broker nor home
lock descriptors reach it. The verified executable descriptor is intentionally
inherited. The explicit credential store override is `ephemeral`.

## Source and output admission

Launch homes must be owned by the effective user, mode 0700. Existing `auth.json`
paths, including dangling symlinks, are inspected with metadata only and refused.
Every reserved environment variable conflicts even when empty. The runner never
clears conflicting variables to admit a launch.

Configuration inspection permits absent/empty TOML or the sole setting
`cli_auth_credentials_store = "ephemeral"`. Other credential/provider/helper,
hook, MCP or endpoint settings conflict; unknown keys, malformed TOML and failed
inspection are unavailable. Independent hook/MCP files are also refused.
Project layers follow the selected release's nearest `.git` root discovery,
falling back to the working directory. System or managed configuration layers
require separate qualification and are currently refused if present.
The TOML parser dependency handles quoted/dotted keys and nested tables; the
standard library has no TOML parser.

Prompt files must be regular files without following symlinks in any path component; prompts are UTF-8 and
at most 1 MiB. Models and efforts come solely from the qualified catalog.
Resume is parsed but refused with `lease_harness_unqualified` (69).

Output preflight creates a private staging file in the destination directory.
A symlink/nonregular destination, unavailable directory or changed destination
cannot be published. Only a matching completed turn plus successful cleanup and
release permits a mode-0600 atomic replacement. Errors leave existing output
unchanged and remove staging files. Stdout contains assistant deltas only;
known token bytes and their lowercase/uppercase hexadecimal SHA-256 forms are
redacted across delta boundaries and in the final file. The lowercase form is
the digest sent as `rejected_sha256`; no other token-digest encoding is sent.
Protection retains every initial and renewed token until material is erased.
Vendor stderr, raw frames and vendor error messages are discarded. Pipe-backed
stdout observes context cancellation; an embedding writer must itself provide
bounded writes. Owned token/wire buffers are cleared. Go's runtime and JSON
encoding can create temporary immutable copies, so physical memory erasure is
not promised.

## Renewal and containment

Each refresh callback is bound to the expected vendor account, original RPC ID
and digest of the last delivered token. Renewal cannot extend authorization.
Duplicate callback IDs fail closed. The local cutoff is 8.5 seconds from callback
receipt, leaving the broker its 8-second budget plus transport allowance. Error
or success writes have a 9-second absolute deadline, reserving one second before
the observed 10-second vendor callback bound. Cancelled/late broker results are
erased without a late success reply. Refusal interrupts the active turn and
starts cleanup immediately.

The private guard starts a new Linux session/process group and becomes a child
subreaper. It monitors a dedicated runner lifeline pipe; SIGKILL of the runner
closes that pipe without relying on an exit callback. On stop/death, the guard
signals only members of its own group through identity-pinned Linux pidfds,
escalates to SIGKILL, and reaps adopted children. The `x/sys/unix` dependency
provides explicit pidfd open/send operations; unsupported kernels remain
unqualified. Group membership is rechecked after opening each pidfd so PID
reuse cannot signal another process. The runner requires a successful guard exit, a fresh successful `/proc` group scan and `ESRCH`
from a group-existence probe after waiting for the guard. Child exit alone is
insufficient; partial/unreadable process evidence remains unknown. Per-PID
metadata reads returning `ENOENT` or `ESRCH` mean that PID disappeared, including
a process reaped after its stat descriptor was opened. Enumeration failures
remain unknown; the owned group still requires every absence check above.

A descendant that changes its process group/session is adopted by the subreaper
when its parent is stopped. The guard also discovers and stops its direct adopted
children using identity-pinned pidfds, regardless of their group, and requires
`wait4` to report no remaining children before success. Double-fork/session escape
cannot be treated as an empty group. A malicious same-UID process is outside
[interim R2](../spec/v0-codex-refresher.md#21-interim-run-identity). This package
makes no cgroup or node-wide containment claim.

A home lock is retained by the guard until descendant cleanup. Before starting
any process, a durable unresolved-intent marker fences home reuse. Clean cleanup
removes it. Runner/guard death or uncertain cleanup leaves the marker; later
runs refuse `lease_owner_unavailable` (75). Recovery requires separately reviewed
reconciliation; deleting a marker is not proof of process absence.

Cleanup uses a separate five-second total budget: bounded interrupt transport,
up to 3.5 seconds for process confirmation (including a 100 ms stdin drain), then
the remaining time for a
release receipt (at most two seconds). The guard's own stop loop is bounded to
three seconds. Adapters must honor this shared deadline. Renewal/cleanup/output
failure is 75 and dominates vendor success/failure. Otherwise statuses are
0 (completed and cleaned), 1 (failed/interrupted vendor turn), 64 (invalid input),
69 (admission/source/qualification/initialization refusal), 124 (execution
deadline) and 130 (handled signal after cleanup).

## Validation boundaries

`internal/runner/testdata/appserver` is a Go stdio fake, built by the runner tests together
with the command. It scripts initialization/login refusal, completed/failed turns,
refreshes, approvals, mismatches, and SIGTERM-ignoring descendants. Tests use an
in-process fake broker, privately qualified fake executable and synthetic tokens.
They include real process-group observation and `/proc` child argv/environment
inspection. No production qualification is created by these tests.

Development runs explicitly skip the proc-disappearance tests when `strace` is
missing. For qualification evidence, require their observations with:

```sh
RUNNER_QUALIFICATION=1 GO="$CURATOR_GO" GOTOOLCHAIN=local "$CURATOR_GO" test -race ./internal/runner -count=1
```

The required rows are all four `TestCommandProcDisappearance` cases and
`TestStopProcDisappearance`, together with their parent test. Each registers
`requiredEvidenceRow` before any possible skip. In this mode, missing `strace`
fails immediately; any required row calling `Skip` also fails in cleanup. Both
paths name the row as `UNVERIFIED`. New required rows must register the same
guard at entry, including parent tests. `TestQualificationMode` controls missing
strace and an explicit required-row skip in subprocesses: development permits
the skips, qualification rejects them. This test mode does not grant production
release qualification or alter runtime admission.

Real-release qualification remains gated by the profile. In particular, full
runner inference against a fake backend requires overrides the production runner
must refuse. Separate empty-home binary probes can establish protocol behavior;
they cannot make the production runner qualified or stand in for approved live
account tests.

## Cancellation and integration limits

RPC pipe writes install a deadline and a cancellation callback that expires it
immediately. The callback is joined before another send, so cancellation cannot
expire a later cleanup interrupt. Cancellation also expires the RPC scanner's
read deadline; receive waits select on the context. The process stop path closes
both pipes and confirms the guard and descendants absent. Stdout pipe writes use
the same joined cancellation callback and clear the borrowed write deadline.
When that deadline interrupts stdout, successful cleanup preserves status 130
for cancellation or 124 for execution expiry. Genuine output failures retain 75,
and cleanup or renewal failure still dominates cancellation. Only stops observed
from the execution context or its own descriptor deadline carry an internal
provenance marker. A bounded embedding writer's independent context error is an
output failure (75), for both streaming and final-buffer flush.

Broker calls, connection establishment and authority loading receive contexts.
Their trusted adapters must honor them; an arbitrary blocking implementation
cannot be forcibly interrupted by this package. Renewal additionally has its
existing asynchronous cutoff, with Close and a bounded wait during cleanup.
Prompt acquisition returns on parent cancellation before any lease/process
starts; embedders should supply cancellable readers so an abandoned prompt read
can also end. Diagnostics use fixed metadata and an embedding writer must have
bounded writes.

Output staging and publication use regular files, with publication after process
teardown and lease release. Regular-file writes, fsync and filesystem metadata
calls have no portable Go cancellation mechanism; a stalled filesystem can delay
command return. Deadline handling for pipes does not establish a storage-latency
guarantee. Existing atomic-publication and failure-preservation checks still
apply.

The package is internal to this module; no external Go API is promised. Helper
tests use `GO` when explicitly supplied, otherwise `runtime.GOROOT()/bin/go`,
and assert both built helpers have the running test binary's Go version. For a
toolchain with no embedded GOROOT, set `GO` to the absolute selected Go executable.
